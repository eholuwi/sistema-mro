── Parte 2/3 — Backup: destino novo e defeito corrigido ───────────────────────

🐛 **Backup pré-migração esperava o busy_timeout e ignorava SQLITE_BUSY**

`criar_banco()` chamava `_backup_db("pre-monitor-sc-v390")` com a **própria transação ainda aberta**.
Como `_backup_db` abre uma SEGUNDA conexão para rodar `PRAGMA wal_checkpoint(TRUNCATE)`, o checkpoint
ficava preso o `timeout` inteiro e devolvia `SQLITE_BUSY`.

O ponto que escondia o problema: **`PRAGMA` não levanta exceção**. O BUSY vem como valor de retorno
`(1, n, n)`. O `except` do `_backup_db` nunca via nada e o método logava "Backup do banco criado"
normalmente. Dois efeitos:

- **Correção:** o `.bak` era gravado **sem o conteúdo do WAL**, logo antes de uma migração destrutiva —
  exatamente a garantia que a função existe para dar. O mesmo valia para `_backup_db("req-status-v470")`
  dentro de `_migrar`, pior ali: o backup precede um `UPDATE` que reescreve as requisições legadas.
- **Performance:** 5,6 s perdidos por banco criado. Na suíte, que cria um banco isolado por teste,
  isso somava **~47 min** e tornava `pytest` inviável como gate de verificação.

Correções:
- `conn.commit()` antes dos dois backups feitos com transação aberta (`pre-monitor-sc-v390` e
  `req-status-v470`), liberando o lock. Os `CREATE TABLE`/`ALTER TABLE` anteriores são idempotentes.
- `_backup_db` passa a **checar o retorno** do `wal_checkpoint` e emitir WARNING quando vem BUSY,
  em vez de tratar como sucesso.

**Suíte: ~47 min → 59 s.**

- `services/scm_sync.py::_backup_1x_dia` ajustado para varrer o diretório novo — varrendo o antigo,

── Parte 3/3 — Empacotamento e instalação ─────────────────────────────────────

🚀 `deploy/iniciar_mro.bat` (NOVO)
- Sobe o Streamlit pelo Python embeddable, define `MRO_DB_PATH`, cria `dados\` se faltar e propaga o
  código de saída para o Agendador de Tarefas reiniciar em caso de queda.

🔄 `deploy/atualizar_mro.bat` (NOVO)
- Para a tarefa → backup do banco → guarda a versão anterior em `app_anterior\` → extrai a nova →
  religa. **Aborta a atualização se o backup falhar** e restaura sozinho se a extração falhar.

📦 `scripts/release.py` (NOVO)
- Gera `dist/mro-<versão>.zip`. Versão lida de `ui/sidebar.py` (fonte única).
- **Inclusão explícita, não exclusão:** um pacote que erra para o lado de "levar demais" vaza
  `mro.db` ou `vault/` num zip que circula por e-mail/pendrive.
- A config de produção entra como `.streamlit/config.toml` do pacote.

📚 `docs/INSTALACAO_SERVIDOR.md` (NOVO)
- Layout `C:\MRO\`, runtime embeddable, migração do banco existente (incluindo `-wal`/`-shm`),
  Agendador de Tarefas, firewall 8501, verificação, atualização, rollback, backup/restore e
  limitações conhecidas (sem autenticação; ponto único de falha).
