# Fluxo de Desenvolvimento

## 1. Contexto

Toda mudança deve começar pelo problema real, pelos dados que ele afeta e pelo impacto operacional.

## 2. Planejamento

- Definir escopo.
- Mapear arquivos afetados.
- Identificar riscos.
- Definir testes e validação.

## 3. Implementação

- Trabalhar por camada.
- Evitar duplicação.
- Preservar compatibilidade com dados existentes.

## 4. Validação

- Executar testes unitários e de integração.
- Verificar comportamento no app real.
- Confirmar backup e rollback quando houver mudança de schema.

## 5. Documentação

- Atualizar documentação relevante.
- Registrar versão e impacto no changelog.
